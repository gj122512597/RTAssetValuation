## 修复：api 镜像在客户空数据卷首启崩溃（`no such table: hedonic_models`）
根因两处（本地开发因 db 文件已存在而长期未暴露）：
1. `server/src/routes/models.ts` 顶层直接 `ensureSeed()` —— ESM import 求值早于 `index.ts` 主体的 `initSchema()`，空库时查 `hedonic_models` 必崩。改为 `export function ensureSeed()`，由 `index.ts` 在 `initSchema()` **之后**调用（顺序：initSchema → ensureModelSeed → initTrainingSamples）。

已重建 api 镜像并用全新空卷验证通过（healthy，/health 200，/api/models/hedonic/comparative 返回模型），`rt-asset-arm64-images.tar` 已重新导出。

## 修复：Hedonic 训练页「重训模型」报 500 spawn python3 ENOENT
根因（api 容器 `node:20-alpine` 缺失 Python 相关全部链路）：
1. 镜像无 python3 → `spawn python3 ENOENT`（直接报错）。
2. `fit_hedonic.py` 未被 COPY 进 runtime 镜像（route 解析路径 `/app/dist/scripts/fit_hedonic.py`），文件缺失。
3. 脚本 `import numpy`，alpine 默认 python3 无 numpy。
4. 脚本原硬编码 `_ROOT = 上溯 4 层` 求 DB 路径，仅匹配本地 `server/src/scripts` 布局；容器内放 `/app/dist/scripts` 会上溯到 `/`，错位。
修复：
- `server/Dockerfile` runtime 阶段 `RUN apk add --no-cache python3 py3-numpy`；并 `COPY --from=builder /app/src/scripts/fit_hedonic.py ./dist/scripts/fit_hedonic.py`。
- `server/src/scripts/fit_hedonic.py`：`DB_PATH = os.environ.get("DB_PATH") or os.path.join(_ROOT,"data","rt_asset.db")`，优先用与后端一致的 `DB_PATH` 环境变量（容器内 `/app/data/rt_asset.db`）。
验证：容器内 `python3 3.12` + `numpy 2.3.5` 可用、脚本就位；启动容器触发 seed 后 `POST /api/training-samples/refit` 返回 `{"ok":true}` 并打印真实系数/R²（comparative/historical 两模型均已写库）。
已重建 api 镜像（`d7cbfe41d881`）并重新 `docker save` 进 `rt-asset-arm64-images.tar`（现 109M，含 python 层）。
